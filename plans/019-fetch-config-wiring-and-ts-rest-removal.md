# 019 — config wiring and `@ts-rest/core` removal

See `011-fetch-overview.md` for full context. Depends on all prior `01x-fetch-*` tasks.

## Purpose

Wire the new `src/fetch/` module into the package's build/export config, add
`@standard-schema/spec` as a real dependency, and remove `@ts-rest/core` entirely now that nothing
in `src/` depends on it.

## Files to modify

### `vite.config.ts`

Add to `pack.entry`:

```ts
entry: {
  index: './src/index.ts',
  error: './src/error/index.ts',
  fetch: './src/fetch/index.ts',
  'react-query': './src/react-query/index.ts',
},
```

Add to `pack.exports.customExports`:

```ts
'./fetch': {
  types: './dist/fetch.d.mts',
  import: './dist/fetch.mjs',
},
```

### `package.json`

- Add `@standard-schema/spec` to `dependencies` (catalog-pinned if a catalog entry exists/is
  added, matching `spin-delay`/`use-deep-compare`'s existing pattern there).
- Remove `@ts-rest/core` from `peerDependencies`.
- Do **not** hand-edit the `exports` field — it's regenerated by `vp run build` from
  `vite.config.ts`.

## Verification (final, whole-package)

1. `grep -rn "@ts-rest/core" src/` — zero matches.
2. `vp check --fix` — lint/format/typecheck clean across the whole package.
3. `vp run test --browser.headless` — all suites (node, browser-chromium, browser-firefox, types)
   pass; coverage thresholds (80% branches/functions/lines/statements) hold repo-wide including
   all new `src/fetch/**` and `../src/error/network-standard-schema-validation-error.ts` files.
4. `vp run build` — confirm the `./fetch` subpath builds, and inspect the regenerated
   `package.json` `exports` field to confirm `"./fetch"` now appears alongside `.`, `./error`,
   `./react-query`.
5. Manual smoke: a throwaway script (or a lightweight test) using `defineContract` +
   `createFetchClient` against an `msw` handler, confirming inferred types match at each call site
   (no `any` leakage) and each error subtype throws in its corresponding failure scenario — this
   can reuse the assertions already written in task 018's tests rather than being a wholly new
   script.
